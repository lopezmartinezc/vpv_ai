## 3. Activar `match_page` en la temporada 12

Opt-in por temporada (no afecta a temporadas anteriores, que siguen en
`player_page`). Necesario para la atribución de equipo por jornada.

`tournament_config` debe quedar como un **objeto** JSON (`{...}`). NO usar
`COALESCE(...) || '{...}'`: si el valor almacenado es una lista (p. ej. `[]`),
`||` anexa el objeto y deja una lista (`[{...}]`), que `stats_source_for`
descarta → volvería a `player_page`. Usar un `SET` directo:

```bash
# Ver el tipo actual (debería quedar 'object' tras el SET)
psql -U vpv -d ligavpv -c "SELECT id, jsonb_typeof(tournament_config) AS tipo, tournament_config FROM seasons WHERE id = 12;"
psql -U vpv -d ligavpv -c "UPDATE seasons SET tournament_config = '{\"stats_source\":\"match_page\"}'::jsonb WHERE id = 12;"
psql -U vpv -d ligavpv -c "SELECT id, name, jsonb_typeof(tournament_config), tournament_config FROM seasons WHERE id = 12;"
```

## 5. Verificación

```bash
# Equipos por jornada asignados (no NULL, coherentes con el partido)
psql -U vpv -d ligavpv -c "SELECT ps.matchday_id, t.name AS equipo, COUNT(*) FROM player_stats ps JOIN players p ON p.id=ps.player_id JOIN teams t ON t.id=ps.team_id JOIN matchdays md ON md.id=ps.matchday_id WHERE md.season_id=12 AND md.number IN (1,2,3) GROUP BY 1,2 ORDER BY 1,2 LIMIT 20;"
# Posiciones rellenas
psql -U vpv -d ligavpv -c "SELECT position, COUNT(*) FROM players WHERE season_id=12 GROUP BY 1 ORDER BY 2 DESC;"
```

## Rutina diaria (hasta el draft)

Cuando se hayan jugado partidos nuevos:

```bash
cd /opt/vpv/backend
.venv/bin/python -m src.features.scraping.cli update-calendar 12
.venv/bin/python -m src.features.scraping.cli scrape-matchday 12 <N>
```

Plantillas (altas/bajas/traspasos) — no es diario; con `match_page` los
traspasos ya no rompen el histórico, pero para altas nuevas y bajas conviene
reconciliar de vez en cuando y **obligatorio antes del draft**:

```bash
.venv/bin/python -m src.features.scraping.cli sync-rosters 12
.venv/bin/python -m src.features.scraping.cli refresh-positions 12   # rellena posiciones vacías de altas
```

## Notas

- **Marca/AS**: tras el re-scrape vienen de la ficha de partido (`match_page`).
  Contrastar 2–3 jugadores conocidos contra la realidad; si algo no cuadra,
  revisar el parser.
- **Bloqueo de posición por eras**: fuera de la ventana pre-draft
  (`current_md < matchday_start`) y del re-sync de invierno
  (`current_md == matchday_winter`), `refresh-positions` solo rellena posiciones
  vacías y nunca pisa una fijada. Es el comportamiento buscado.
- **Draft de invierno**: cuando llegue, fijar `seasons.matchday_winter` de la 12
  para abrir la ventana de re-sync de posiciones en esa jornada.
